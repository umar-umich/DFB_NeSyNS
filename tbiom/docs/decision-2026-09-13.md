# Decision record — 2026-09-13

## Decision

Provisionally select **arm B** (common pipeline + class-balanced processing exposure). Pause
SBI and FreqBlender. Resolve the A − R0 difference before committing more training. B has the
strongest evidence of improved processing stability but is **not** a confirmed overall winner.

## Direction change

Missing measurements and symbolic decision rules are not explaining the main failures.
**Processing sensitivity** and **missing temporal information** are the better-supported targets.

- Three-state availability stays as correct interface behaviour, not the paper's central
  empirical claim: availability was 1.0 on all 534,250 frames, so a masked-input pass does not
  demonstrate benefit on naturally missing measurements.
- The vacuity partial correlation (+0.284) is association with one diagnostic, not validation of
  epistemic uncertainty.
- The current claim is provisional: a study of processing sensitivity, false-alarm trade-offs and
  limits of multiview evidential fusion. It does not establish a reasoning mechanism that improves
  detection.

## Execution order

1. **Loader / pipeline audit of A vs R0.** Deterministic, no retraining. If an implementation
   error is found, fix it and establish the matched baseline before confirming B.
2. **Paired A/B confirmation on seeds 1337 and 7** (B against A, not B alone). Report per dataset
   and processing condition: absolute clean and processed FPR/TPR at dev-fixed thresholds, change
   from clean, processed AUROC, and processed TPR at matched FPR (retrospective, labelled).
   B advances only if it beats A on the trade-off, not merely by changing less from a weaker start.
3. **Neural and calibration controls** on the confirmed detector's measurements: same-input
   neural head, a simple calibration baseline, then the probabilistic comparison. Symbolic
   constraints only where a concrete behaviour to improve can be named.
4. **Small temporal probe**: frame representation aggregated over a clip vs an order-sensitive
   temporal representation on the same frames vs temporally shuffled clips, on the hard
   reenactment generators at matched genuine-video FPR, including unfamiliar genuine clips with
   natural motion, tracking errors and processing changes. V-JEPA is a candidate encoder. No
   real-only prediction-error model, new uncertainty mechanism or symbolic program in the first
   comparison.

Optional, secondary: after an SBI integration audit, one predeclared low-fraction SBI arm
(e.g. 10%) against B. FreqBlender only after that SBI recipe proves a useful foundation. Changing
the SBI fraction and adding FreqBlender together is ruled out — two factors at once.

Baseline priority: the untrained **concat-CE** control under the same processing recipe. It changes
fusion and loss together, so it tests the complete alternative, not EDL alone. The single-seed
native-CE comparison (+0.0079) cannot carry an EDL-superiority claim.

## Audit findings so far (2026-09-13)

- **The arm-A loader wrapper is inert**: identical sample IDs, labels and metadata; bit-identical
  image tensors with augmentation off and on under matched RNG; bit-identical evidence from one
  frozen checkpoint (`tbiom/reports/AUDIT_LOADER.md`). Steps per epoch (900), epochs and per-epoch
  val AUROC match R0 within ±0.0005.
- **Checkpoint selection was not matched.** R0 used epoch 5. The SBI drivers took the newest file
  (`ls -t`), an undeclared rule: A → epoch 14 (tied best), B → epoch 11 (tied best), and
  **C → epoch 04 (0.9863), not its best epoch 02 (0.9869)**. All SBI arm numbers reported so far
  sit on this rule and are provisional until re-exported under one declared rule.
- **The arm C CDFv3 loss was misattributed in the status file.** C improves on all eight CDFv3
  face-swap subsets (+0.015 to +0.045). The loss is reenactment and talking-face, where C scores
  below chance on seven generators (AUROC 0.13–0.32) and rates CDFv3 genuine videos at mean
  p_fake 0.971, above the fakes (0.924). Hypothesis, untested: SBI teaches "blending boundary =
  fake", and whole-frame generation has no boundary. Not to be tuned against.

## Declared checkpoint rule (fix for the selection mismatch)

All runs — R0, A, B, C, and every later seed — use **one** rule: `analysis/tbiom/stage23_select.py`,
the project's existing dev procedure. Every saved checkpoint is exported on FF++ val and VALmix
only; the checkpoint with the highest **VALmix macro AUROC** is selected, with FF++ val AUROC logged
as a guardrail. Ties break to the earliest epoch. No OOD set is opened for selection.

This replaces the newest-file rule the SBI drivers used and applies to R0 as well. R0's canonical
epoch 5 was chosen on FF++ val in Phase F (candidates within 0.0001), so R0's selected checkpoint
may change; if it does, R0 is re-exported under the same rule so all four runs stay matched.

Driver: `analysis/tbiom/reselect_checkpoints.sh` (dev exports only). After it completes: run the
selector per run, re-export the six OOD sets for any checkpoint that changed, rescore the arm
table, and rerun the per-arm processing test. Until then every SBI arm number is provisional.

## SBI integration compatibility check

- **No genuine-only objective exists** that could be misapplied to pseudo-fakes. The only
  label-dependent terms are the fused and per-branch evidential losses, which use the item's label
  (1 for SBI fakes). The β-VAE alignment loss and the FS-VFM branch take features, not labels.
- **Synthetic images reach every branch consistently**: all three views are computed from the same
  input tensor in one forward pass, and SBI images use the detector's own CLIP preprocessing.
- **Metadata caveat**: an SBI item keeps the `identity`, `source` and `idx` fields of the FF++ fake
  slot it replaced. No loss reads `identity` or `source`; `idx` only maps training predictions to
  file names for logging. Harmless now, but any future source-aware loss must not trust these fields
  for SBI items.

### Correction 1 — "B has stable sensitivity under processing" is withdrawn

The pre-v2 per-arm processing test reported B's mean ΔTPR as −0.031 and called B the only arm whose sensitivity
held. That mean averaged opposite-signed shifts and hid them. Under v2, at B's own τ:

| condition | B: ΔFPR_real | B: ΔTPR |
|---|---:|---:|
| CDFv2 jpeg q40 | +0.124 | +0.138 |
| CDFv2 resize 0.60 | −0.028 | −0.197 |
| DFDCP jpeg q40 | +0.087 | +0.101 |
| DFDCP resize 0.60 | −0.048 | −0.111 |

B's operating point is **not** stable: JPEG shifts its scores up, raising false alarms, while resize lowers
detection. Its lower clean FPR_real (0.117 vs A's 0.203) comes with lower clean TPR (0.659 vs 0.792) and a higher
τ, so it is largely a threshold shift. Per-condition changes must be reported; averaged ΔTPR/ΔFPR across
processing conditions is not used again.

What survives: **B ranks fakes better under processing in 3 of 4 held-out conditions** — processed AUROC A→B
0.793→0.873 (CDFv2 jpeg), 0.867→0.899 (DFDCP jpeg), 0.830→0.888 (DFDCP resize); worse on CDFv2 resize
(0.924→0.901). Retrospective TPR at FPR 0.10 follows the same pattern. Clean mean AUROC is unchanged (B−A +0.0008).
The candidate claim is therefore **ranking robustness under processing, not threshold stability**, and deployment
would need recalibration.

### Correction 2 — "SBI improves face-swap subsets" is withdrawn

The pre-v2 arm C (epoch 04) appeared to improve all eight CDFv3 face-swap subsets over B. Under v2, mean CDFv3
subset AUROC by manipulation group:

| group | R0-v2 | A-v2 | B-v2 | C-v2 |
|---|---:|---:|---:|---:|
| face swap (8) | 0.939 | 0.923 | 0.909 | 0.916 |
| reenactment (7) | 0.895 | 0.877 | 0.878 | 0.361 |
| talking face (7) | 0.862 | 0.847 | 0.863 | 0.552 |

C's swap advantage over B is +0.007 (within noise) and C is below A and R0 on swaps. Nine CDFv3 subsets fall below
chance. The finding is **roughly neutral on face swaps, severely harmful on reenactment and talking face**.
